# 宿主平台适配

本技能设计为**平台无关**：核心工作流（需求确认 → 生图 → 后处理 → 交付）在任何支持"写文件 + 执行命令"的 agent 平台上都能跑。本文件记录两类平台特有内容。

## 一、宿主内置生图能力的调用参数

以 WorkBuddy 的内置生图工具 `ImageGen` 为例 —— 其它平台若有等价工具，参数含义通常类似。

| 参数 | 建议值 | 说明 |
|---|---|---|
| `prompt` | 见 `prompts.md` | 必须显式锁发型 + 锁身份 + 写鼻子对称 |
| 参考图（`image1`） | 底图的绝对路径 | 传了就是**图生图**。必须用最正面、最清晰的那张 |
| `size` | `1024x1536` | 竖版人像，比例接近 1 寸 |
| `quality` | `high` | |
| `input_fidelity` | `0.85` | **低于 0.7 会开始改脸，高于 0.9 改动不明显** |
| `output_dir` | 每款单独子目录 | 避免文件混淆，便于建立"文件 ↔ 款式"对应关系 |

**限制**（实测）：

- 输出分辨率上限约 1.5 K 级。请求 `2448x3264` / `2048x3072` 会返回"尺寸不支持"→ **无法用它产出超清版**，超清档只能走第三方 API 或本地插值。
- 输出**常带右下角水印**，必须用后处理脚本 inpaint 去除。
- **并发提交会报 `error request aborted`，必须串行。**
- 人物保真倾向整脸重绘（磨皮 + 瘦脸 + 提亮），**局部微调几乎无效**。

> 需要"只改某处五官且不磨皮"时，不要用生成式通道，走 `liquify-geometry-retouch.md` 的液化法。

## 二、交互式需求确认

动手前必须问清需求，**发型是必问项**。用平台提供的提问组件（WorkBuddy 为 `AskUserQuestion`）一次性给出选项，不要让用户逐条回复。

推荐的问题结构：

1. **发型**（单选，核心开关）
   - 保持现有发型 → 只换衣服和背景，脸和头发 1:1 保留
   - 换一款新发型 → 进入发型推荐环节
   - 两种都要，给我对比 → 两个模式各生成一套
2. **具体发型款式**（仅当选了"换发型"时问，多选）
   - 从 `hairstyles.md` 按脸型挑 4–5 款，每款附一句话说明
   - **不要一次列超过 5 款**，会造成选择困难
3. **输出偏好**（可并入第 1 题）
   - 衣服颜色：深蓝 / 黑色 / 深灰 / 让模型挑
   - 用途：驾照 / 简历 / 签证 / 其他（影响风格建议）
   - 底色：白 / 蓝 / 红

## 三、结果交付

- 用平台的文件展示能力一次性给出全部成片（WorkBuddy 为 `present_files`），不要一张一张发。
- 交付时附**款式说明**与**推荐用途**，并给出下一步选项（换款 / 换底色 / 微调）。
- 若产出了多档规格，明确告诉用户哪一份是主交付。

## 四、技能安装位置

| 平台 | 技能目录 |
|---|---|
| WorkBuddy（用户级） | `~/.workbuddy/skills/<skill-name>/` |
| WorkBuddy（项目级） | `<project>/.workbuddy/skills/<skill-name>/` |
| Claude 等兼容 agent | 平台对应的 skills 目录 |

安装方式：把本仓库的 `skill/` 目录整体拷贝过去并重命名为技能名即可。SKILL.md 自洽，references 之间的引用路径为相对路径。

## 五、脚本运行环境

脚本依赖 `pillow`、`opencv-python`、`numpy`（`nose_symmetry_fix.py` 另需 `mediapipe==0.10.35`）。

**必须装在隔离虚拟环境，不要全局 `pip install`** —— 全局安装会污染用户其它项目，可能导致依赖版本冲突。

```bash
# 检查当前解释器是否已有依赖
python3 -c "import PIL, cv2, numpy" 2>/dev/null && echo "依赖已就绪"

# 缺失则建虚拟环境（不要 sudo，不要全局装）
python3 -m venv ~/.venvs/idphoto
~/.venvs/idphoto/bin/pip install pillow opencv-python numpy

# 用虚拟环境的解释器运行
~/.venvs/idphoto/bin/python <skill-dir>/scripts/process_id_photo.py <输入图> --outdir <输出目录>
```

> 若当前会话已有可用的隔离环境（如宿主的托管 Python 环境），**优先复用**，不要重复创建。
