# 通道 A：第三方图生图 API（以美图设计室 designkit 为例）

面向"整体重制"类需求 —— 换底色 / 换衣服 / 换发型 / 规格重制。这类需求需要重新绘制整张图，不是局部修补。

本文以**美图设计室 CLI（`designkit`）**为具体实例。若你使用其它图生图 API，把第 3 节的调用链换成对应服务的四步（建会话 → 发指令 → 轮询结果 → 下载产物）即可，其余章节的方法论通用。

## 一、两条生图通道对比

| 维度 | 宿主内置生图 | 第三方 API（designkit） |
|---|---|---|
| 性质 | 开箱即用，无需安装 | 第三方 CLI，需自行安装 + 浏览器授权登录 |
| 调用方式 | 工具调用（prompt + 参考图 + 保真度参数） | 命令行四步：建房 → 发指令 → 轮询 → 下载 |
| 输出分辨率 | 通常 1 K 级，超 2 K 常报"尺寸不支持" | 实测最高可达 2448×3264（**须 prompt 显式要求**） |
| AI 水印 | **常有右下角水印**，必须 inpaint 去除 | 无水印，后处理可跳过 inpaint |
| 人物保真 | 倾向整脸重绘（磨皮 + 瘦脸 + 提亮），局部微调几乎无效 | 与底图一致度高，能保留五官细节 |
| 并发 | 并发提交会报错，必须串行 | 并发开多个会话会互相抢额度 |
| 计费 | 宿主额度 | 第三方额度（本项目实测约 15–20 单位/张） |

**结论**：整套重制优先第三方 API；两套额度互相独立，可互为备份应急。但**同一批产出不要混用通道** —— 光影与质感会不一致，用户一眼能看出来。

## 二、安装与登录

```bash
npm install -g meitu-designkit-cli     # 需用户自己在终端执行（涉及 npm 全局安装）
designkit --version                     # 例：1.0.63
designkit auth status                   # 期望输出 connected
designkit user-info                     # 查余额：coinInfo.available_amount
```

- 登录走浏览器授权，需用户配合操作一次
- 余额查询见 `user-info` 输出，或 https://www.designkit.cn/openclaw

## 三、四步调用链

```bash
# ① 建房（记录返回 JSON 里的 room_id）
designkit create-room
# → {"room_id":"<room-id>","room_url":"https://www.designkit.cn/ai-agent/team?room_id=..."}

# ② 发指令（--image-file 传本地图，单张 ≤20MB）
designkit chat -p "<中文需求，见下方 prompt 三要素>" \
  --room-id "<room-id>" \
  --image-file "/path/to/base-photo.png"
# → {"task_id":"<task-id>","room_id":"...","room_url":"..."}

# ③ 轮询结果（--watch 阻塞直到出图）
designkit history-detail -r "<room-id>" --watch
# → 正常：{"event":"history_update", ..., "artifacts":[{"media_url":"https://...png"}], "next_action":"poll"}
# → 额度不足：{"event":"recharge_required", ..., "action_command":"designkit resume ..."}

# ④ 下载（会把该会话内全部产物拉到本地）
designkit download -r "<room-id>" -o <输出目录>
```

**要点**

- `create-room` 后**立刻把 room_id 存下来**（如 `echo "$ROOM" > /tmp/room.txt`），中途丢了就得重建、重新扣额度
- prompt 用**中文**即可（`--lang` 默认 `zh-Hans`），比英文 prompt 更好写
- 一个会话可发多条指令，产物累积在同一历史里；`history-detail` 与 `chat` 的 room_id 相同
- 输出尺寸由模型决定（实测 1728×2304 / 2448×3264 都可能），**不要指望它直接给你目标尺寸**，仍要用后处理脚本统一裁切缩放

### prompt 三要素

1. **保持身份**：保持同一个人的脸型、五官、表情和正面角度完全不变，面部平衡对称，鼻梁笔直居中，鼻孔均匀、鼻翼对称
2. **显式要求分辨率**（见第 4 节，漏写必糊）
3. **场景描述**：服装 + 背景 + 证件照风格 + 输出比例

> 鼻子对称描述**必须默认写进 prompt**。不加时模型极易生成左右不对称的鼻翼/鼻孔。

## 四、输出分辨率由 prompt 决定（血泪）

**不写分辨率要求，可能只给 800×1120**，放大到 1181×1653 后细节偏糊，用户会投诉"清晰度不够"。

prompt 里必须显式写：

```
要求输出高分辨率大尺寸图片（分辨率不低于2K，宽边至少2000像素，越高越好，参照2448x3264）
```

实测效果：

| prompt 写法 | 输出分辨率 |
|---|---|
| 只描述内容（默认） | 800×1120 |
| 加一句"高分辨率大尺寸" | 1536×2048 |
| 加"宽边 ≥2000px，参照 2448×3264" | **2448×3264 / 2400×3200** |

拿到高分辨率源图后再交给后处理脚本缩放，才能真正提升成片清晰度。

> **判断成片是否够清晰，别看文件体积**。实测过：369 KB 的成片比 411 KB 的更锐（Laplacian 100 vs 148）。
> 要用 Laplacian 方差 / 边缘梯度做客观测量，统一缩放到同宽再比 —— 详见 `quality.md`。

## 五、皮肤质感是 prompt 可调的

不同模型的默认皮肤倾向不同：有的默认带轻度美颜（肤色亮、均匀、润泽），有的在「不要磨皮」约束下保留毛孔纹理、偏干哑光。用户可能主观更喜欢"润"的那版，但政务照走真实路线过审更稳 —— **先问清用户要哪种，再定 prompt**。

| 用户想要 | prompt 里皮肤部分写 |
|---|---|
| 真实原生（默认，过审稳） | 「不要磨皮」 |
| 折中（细腻但有纹理） | 「皮肤自然细腻、肤色均匀有光泽、保留真实纹理但去除瑕疵」 |
| 精修感（观感好，过审有风险） | 「皮肤光滑细腻、肤色白皙透亮」，或改用默认带美颜的通道 |

- 对比两个通道的皮肤时**必须同底图、同装、同发型**，否则衣服反光和发型光影会污染结论
- 该差异是模型默认行为，不是某个通道的缺陷；要如实告知用户两条路线的取舍

## 六、额度用尽怎么办

```json
{"event":"recharge_required","available_amount":0,
 "action_command":"designkit resume --room-id '<id>' --task-id '<id>' --after-seq <n> --reason recharge"}
```

- **不要反复重试**：额度不够时重发和重试都不出图，只是浪费时间
- **不要并发开多个会话**：会互相抢额度，两边都中途失败
- 正确做法：把 `action_command` 原样交给用户，让他充值后**原命令续跑**（断点续传，不会重复扣除前面已出的图）
- 充值后 `resume` 会返回 `{"event":"recharge_resumed","available_amount":<余额>}`，随后 `history_update` 给出新产物

> **断点记录的四个值**：`room_id`、`task_id`、`after-seq`（上次中断的序号）、以及原始 prompt 原文。
> 把它们完整写进交接文档 —— 换新会话重发不仅重新扣费，产出还可能与已出的一批不一致。

## 七、批量重制 + 安全替换流程（重要）

用户要求"整套重新生成"时，**不要直接覆盖既有成片**。标准动作：

```
1. 产出落副本目录        → <workdir>/new-<source>-<date>/
2. 拼对比图给用户看      → 上=旧版 / 下=新版，用户指哪款不行就单点重做
3. 备份正式目录          → <workdir>/backup-gen<N>-<date>/，用 md5 汇总校验
4. 覆盖正式目录          → cp -f 新版 → 正式目录
5. 校验替换结果          → 正式目录与新版源 md5 一致
6. 存档对比图 + 清理副本  → 对比图另存固定目录；副本用 trash 移废纸篓（可恢复），不要 rm
```

- **覆盖前必须有可回滚的备份**，并在回复里给出回滚命令
- 备份后一定要**逐字节校验**（如 macOS `md5 -q` 汇总比对），不能只看文件数
- 正式目录里若有旧版遗留的额外文件，**保留不删**，问过用户再处理

## 八、踩过的坑

| 坑 | 后果 | 正确做法 |
|---|---|---|
| prompt 没写分辨率要求 | 只出 800×1120，放大后偏糊 | 必写「宽边 ≥2000px，参照 2448×3264」 |
| 并发跑多个会话 | 一起抢额度，两边都中断 | 串行；先 `user-info` 看余额 |
| 同一输出目录先跑高清再跑标准版 | 标准版输出同名文件，**直接覆盖高清版** | 标准版显式指定独立子目录，别在同一目录跑两次 |
| `create-room` 完没存 room_id | 中途断了只能重建，额度白扣 | 立刻写入临时文件 |
| 额度不足时反复重试 / 换会话重发 | 不出图也不省额度，纯浪费 | 拿 `action_command` 让用户充值后 `resume` |
| 一批产出混用两种通道 | 质感/光影不一致，用户一眼看出 | 整批统一，缺的用 `resume` 补齐 |
| 源图已是高分辨率却仍重度锐化 | 过锐出光晕 | 锐化按缩放比自适应，输出锐度控制在源图 1.1 倍以内 |
| 直接 `rm` 冗余副本 | 无法回退 | 用 `/usr/bin/trash`（macOS）移入废纸篓 |
