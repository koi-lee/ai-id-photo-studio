# 面部对称性精修

证件照对面部对称性很敏感——用户会放大盯着鼻子、眼睛看。这里是踩过坑之后总结的处理路径。

## 一、问题来源

图生图（image-to-image）生成证件照时，**鼻翼/鼻孔不对称**是最常见的残留缺陷：

- 原照片本身有轻微结构不对称（多数人都有），`input_fidelity` 高时被原样继承
- 模型对 `symmetrical nose` 这类指令的响应很弱，只能轻微收敛，做不到精准矫正
- 表现为：一侧鼻翼偏高/偏低、两侧鼻孔大小不一、鼻梁出现轻微偏移感

**结论：不要指望靠 prompt 解决鼻翼不对称。** prompt 里的对称描述只能作为预防手段，一旦已经生成出来，必须靠后处理修。

## 二、三种修正方案（按推荐度排序）

### 方案 A：面部关键点 + 局部液化（推荐）

用面部关键点检测定位鼻翼，只对目标区域做小幅形变。

```bash
pip install mediapipe==0.10.35   # 装到隔离虚拟环境，不要全局安装（见 SKILL.md 第五节）
```

思路：
1. 检测 468 个面部关键点，取鼻翼左右外侧点与鼻底点
2. 计算两侧鼻翼下缘的垂直差值 `dy`
3. 构造一个局部位移场：偏高的一侧向下、偏低的一侧向上，各移动 `dy/2`
4. 位移场用高斯衰减限制在鼻翼周围，避免影响脸颊和嘴唇
5. 用 `cv2.remap` 或网格变形应用

**务必在副本上操作**，确认效果后再覆盖正式文件。

### 方案 B：美图设计室等专业修图 App

把高清图传入美图设计室 App，用「面部精修 / 瘦脸瘦身」推一下鼻翼。用户手动操作最直观，适合 AI 修不出满意效果时的兜底。

> 若当前 agent 平台没有对接该 App 的调用能力，就把它作为"请用户手动处理"的兜底路径，不要试图用生成式修图代替 —— 那会整脸重绘。

### 方案 C：镜像对称融合（不推荐，有坑）

以鼻梁中线为轴，把一侧镜像到另一侧。

**严重的坑**：
- 处理区域的上沿只要碰到鼻梁，就会在鼻梁上留下一条**竖直的融合痕迹**，用户会描述成"眼睛重影"或"鼻子分裂"
- 处理区域过大还会波及嘴唇、法令纹，导致嘴型改变

**如果非要用，必须遵守**：
- box 上沿严格限制在**鼻尖以下**（约 `y = 0.40h`），绝不碰到鼻梁
- box 下沿限制在**鼻孔下缘以上**（约 `y = 0.45h`），绝不碰到嘴唇
- 中线融合带 `band` 不小于 30px

即使遵守上述限制，也会让鼻子两侧完全一致，损失自然度。**优先用方案 A。**

## 四、客观测量：修到什么程度算对称？

用户觉得"鼻子还是歪"时，不要凭感觉，用面部关键点做客观测量：

```python
# 比较左右鼻翼外缘点（468 点 FaceMesh）
dy = pts[129][1] - pts[358][1]
```

| 垂直高度差 | 判定 |
|---|---|
| `< 2 px` | 几何上基本对称（1181×1653 图中小于 0.17%） |
| `2–5 px` | 轻微不对称，用方案 A 修正 |
| `> 5 px` | 明显不对称，必须修 |

**实战经验**：1181×1653 的证件照里，鼻翼高度差 **≤ 1.6 px** 时，用户仍可能说"看着不对称"——这通常不是几何问题，而是**光影明暗**造成的视觉错觉。鼻翼一侧受光更亮、阴影更少时，会显得"更鼓"或"更低"，与真实位置无关。

所以修正流程应该是：
1. 先用关键点测几何差值
2. 几何差 < 2px 仍被用户质疑 → 检查光影，而非继续推鼻翼
3. 光影造成的"不对称"，可尝试用局部 dodge/burn（加深/减淡）平衡两侧阴影，而不是形变

## 六、操作纪律

1. **先在副本上改**，输出到临时目录，让用户确认效果
2. 用户确认后再覆盖正式文件（高清版 + `295x413标准版/` 同步更新）
3. 改完把临时文件清理掉
4. 每次修正都保留原图的备份，避免用户不满意时无法回退
