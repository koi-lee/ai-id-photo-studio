# 标准作业流程

端到端的证件照制作流程。每一步的关键约束都标了出来，照着做不会踩坑。

## 流程总览

```
① 需求确认 ──→ ② 看照片判脸型 ──→ ③ 选通道生图 ──→ ④ 脚本后处理 ──→ ⑤ 交付验收
   （发型必问）                                            │
                                                       ⑥ 局部微调
                                                    （仅当用户对细节不满意）
```

---

## ① 需求确认

**必须问清，发型是必问项。** 用平台提问组件一次性给选项，不要让用户逐条回复。

| 项 | 选项 |
|---|---|
| 发型 | 保持现有 / 换一款 / 两种都要对比 |
| 规格 | 一寸 / 二寸 / 结婚证 / 其他（见 `skill/references/specs.md`） |
| 底色 | 白 / 蓝 / 红 |
| 服装 | 保持原衣 / 换西装 / 换衬衫（选色）；**浅色上衣必须换深色** |
| 性别 | 决定服装库与发型库 |
| 用途 | 驾照 / 简历 / 签证 / 结婚登记（影响风格与合规提醒） |

**同时告知隐私事项**：人脸图片会被发送至第三方生图 API。

## ② 看照片、判脸型

判断脸型（鹅蛋 / 圆 / 方 / 长 / 心形）、当前发型问题、发际线与发量。

在回复里说明判断依据 —— 用户需要知道你是有依据地在推荐，而不是随机出图。

> 亚洲男性"发型扁塌"的常见根源不是脸型，而是**两侧推太光 + 顶部贴头皮**。对策是两侧保留渐变 + 顶部做蓬松纹理。

## ③ 选通道、生图

| 需求 | 通道 |
|---|---|
| 换底色 / 换服装 / 换发型 / 整体重制 | 第三方图生图 API（推荐，见 `platform-designkit.md`） |
| 快速试一版 / 无 CLI 环境 | 宿主内置生图（见 `platform-host.md`） |
| 只改某处五官、不磨皮 | 本地液化（见步骤 ⑥） |

**同一批产出必须统一通道。**

**prompt 四要素**：

1. 面部特征锚定（face_desc）—— 从原图逐项归纳，防被美化
2. 鼻子对称描述 —— 不加极易生成不对称的鼻翼
3. 显式分辨率要求 —— 不写可能只给 800×1120，放大必糊
4. 服装 + 背景 + 证件照风格 + 输出比例

**逐张生成，串行执行。** 每张记下"文件 ↔ 款式"的对应关系。

## ④ 脚本后处理

```bash
<venv>/bin/python skill/scripts/process_id_photo.py 生成的图.png \
  --spec 1inch --outdir ./out --tiers hd,std -n 一寸白底_黑色衬衫_经典正式
```

处理链：去水印 → 规格裁剪 → LANCZOS 缩放 → 自适应 USM 锐化 → 输出 JPEG。

**三条约束**：

- `--spec` 决定比例与尺寸；结婚证用 `--spec marriage`（横版）
- 多档用 `--tiers`，**各档自动输出到独立子目录** —— 手动指定 outdir 时若让标准版与高清版共用目录，标准版会覆盖高清版
- 超清档（`uhd`）在源图裁剪后宽度不足时会**自动跳过**，这是刻意的 —— 放大不产生真实细节

批量处理：把目录路径作为第一个参数传入。

## ⑤ 交付验收

命名：`<规格><底色>_<特征>_<风格>.jpg`

用平台的文件展示能力**一次性给出全部成片**，附款式说明与推荐用途。

**交付时必须说明合规边界**（见下节）。

### 画质验收

用户说"不清晰"时按此顺序排查：

```
① Laplacian 客观测量（统一缩放到同宽再比）—— 体积 ≠ 清晰度
② 查源图分辨率找根因（最常见：prompt 没写分辨率 → 源图仅 800×1120）
③ 修根因（重生成高分辨率源），别盲目调大输出尺寸
```

## ⑥ 局部微调（按需）

用户提出"某处不对称"且要求不磨皮时，**禁用生成式修图**，走液化三步：

```bash
<venv>/bin/python skill/scripts/nose_liquify.py --image 成片.jpg --measure
<venv>/bin/python skill/scripts/nose_liquify.py --image 成片.jpg --ladder 2,4,6,8 --strip 对比条.png
<venv>/bin/python skill/scripts/nose_liquify.py --image 成片.jpg --auto --out 修正.png
```

先量 Δ → 多档对比条让用户挑 → 定稿 → 复测。统一用"画面左 / 画面右"沟通。

## 批量重制 + 安全替换

用户要求"整套重新生成"时的标准动作 —— **不要直接覆盖既有成片**：

```
1. 产出落副本目录        → <workdir>/new-<source>-<date>/
2. 拼对比图给用户看      → 上=旧版 / 下=新版
3. 备份正式目录          → <workdir>/backup-gen<N>-<date>/，md5 汇总校验
4. 覆盖正式目录          → cp -f 新版 → 正式目录
5. 校验替换结果          → 与源 md5 一致
6. 清理副本             → 用 trash 移废纸篓（可恢复），不要 rm
```

备份后**必须逐字节校验**（`md5` 汇总比对），不能只看文件数。

## 合规边界（交付时告知用户）

- 生成的证件照**能否被受理由办理机关判定**，本技能只负责技术实现。
- 政务系统通常要求**真实拍摄的原始影像**，部分会做人脸比对与合成检测。
- **不要过度美颜** —— 除可能被判"非原始影像"，办理时人脸比对也可能不通过。
- **结婚证合影**：登记规范要求双方"同一时间、同一地点共同拍摄"，**不能是合成照片**。生成版仅适合预览风格或情侣写真；正式登记建议实拍 + AI 仅做底色替换与轻度修饰。
- 以当地办理机关的最新要求为准。

## 环境准备

```bash
python3 -m venv ~/.venvs/idphoto
~/.venvs/idphoto/bin/pip install pillow opencv-python numpy
# 需要关键点检测时（nose_symmetry_fix.py）
~/.venvs/idphoto/bin/pip install mediapipe==0.10.35
```

**不要全局 `pip install`** —— 会污染用户其它项目，可能导致依赖版本冲突。
